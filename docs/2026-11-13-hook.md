# The hook, proven on a clean Decidim (November 13, 2026)

Frontdoors gets into a Decidim page through one edit: Deface adds the line
`<% Decidim::Frontdoors.apply(self) %>` to Decidim's `layouts/decidim/_head`, in front of the line that renders
the application's own head content. This file records how that was checked before anything else was built, on
the development application (`rake development_app`: Decidim 0.32.2 as generated, with its seed data), on a
laptop, between 11:13 and 11:20 am Boston time.

"Deface" is a library that changes a template when it is loaded. "The head" is the part of a page the browser
reads before it draws anything. A "crumb" is one link of Decidim's breadcrumb.

## 1. The line runs before the body tag and before the breadcrumb are drawn

For this check only, `apply` was a stand-in of three lines: when the address had `?frontdoor=1` it added a class
to the body tag and removed the first crumb from Decidim's breadcrumb list. If the line ran too late, neither
would show in the page. The page is the seed data's one participatory process, `/en/processes/marine-nursery`.

| The application | Address | The body tag | The breadcrumb's links |
| --- | --- | --- | --- |
| As generated | without the switch | `class="text-black text-md form-defaults"` | Home, Processes, the process group |
| As generated | with `?frontdoor=1` | `class="text-black text-md form-defaults frontdoor"` | Home, the process group |
| With its own `_head_extra.html.erb` | without the switch | `class="text-black text-md form-defaults"` | Home, Processes, the process group |
| With its own `_head_extra.html.erb` | with `?frontdoor=1` | `class="text-black text-md form-defaults frontdoor"` | Home, the process group |

The application's own head file (`app/views/layouts/decidim/_head_extra.html.erb`, the file Decidim provides for
an application's own head content) held a `<meta>` tag and a `<script>` of its own and nothing of Frontdoors. In
both rows with it, the tag and the script were each in the page once. So an installer's head file and the
module's line do not meet: they are different files.

Deface's own log line, on every page: `'frontdoors' matched 1 times with
'erb[loud]:contains('layouts/decidim/head_extra')'`.

development machine compiles without fingerprints).

## 3. What had to be fixed: one line break

The first comparison found every page exactly one byte longer with the module. A Deface file is usually written
on two lines, the instruction and then the code. Deface then put a line break in front of the inserted code, and
that line break reached every page. With the code on the same line as the instruction, the edited template is
Decidim's file plus the one line and nothing else:

| | Bytes | Lines |
| --- | --- | --- |
| Decidim's `_head.html.erb` (decidim-core 0.32.2) | 1,832 | 43 |
| The same after Deface's edit | 1,870 | 44 |
| Difference | 38: the line (37) and its line break | 1 |

Taking that one line out of the edited template gives back Decidim's file exactly. A spec holds both facts
(`spec/lib/decidim/frontdoors/guard_spec.rb`, "the one line Deface adds"), so a Deface or Decidim upgrade that
changes either fails in CI.

## 5. What this does not show

- A real deployment. The check above is the test application in production mode on a laptop, asked by a script;
  no browser, no proxy in front, no service worker. The package has not run on a live site yet.
- Another module's Deface edit on the same template at the same time (decidim-awesome was not installed).
